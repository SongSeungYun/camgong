# Implementation Plan: 전국 대학 가입과 같은 학교 범위

**Branch**: `009-school-scope` | **Date**: 2026-11-19 | **Spec**: [spec.md](spec.md)

## Summary

- 가입 도메인 규칙을 바꾼다: `ac.kr` 접미사를 받고, 그 밖의 대학은 운영자 추가 목록으로 받는다.
- 회원과 공구에 학교 키를 저장한다.
- 로그인한 회원의 목록, 상세, 새 참여는 자기 학교로 좁힌다.
- 비로그인 목록은 전국 공구를 보여주고 학교로 거를 수 있게 한다.
- 계약은 [contracts/school-api.md](contracts/school-api.md).

## Technical Context

기존과 같다: Java 21, Spring Boot 4.1.2, MySQL 8.4(Flyway), React/Vite/TS. 백엔드에서 010보다 먼저 한다(마이그레이션 번호 V2).

## Constitution Check

- N+1·조회 성능(헌법): 목록은 계속 공구 테이블 한 곳에서 조인 없이 읽는다(결정 3). 003 k6 목록 측정을 다시 돌려 전후를 기록한다.
- 테스트 먼저, 문서는 관제탑 소유.

## 결정 (research)

### 1. 학교 키 정하기 (가입 확인 시점, 002 verify)
메일 도메인을 소문자로 바꾸고 앞뒤 공백을 지운 뒤 판정한다(002 정규화와 같다).
1. **추가 목록(운영자 묶음)을 먼저 본다.** 도메인이 묶음의 어떤 도메인과 같거나 그 하위 도메인이면(점 경계), 학교 키는 그 묶음의 **첫 도메인**이다. `ac.kr` 도메인도 묶을 수 있다(교명 변경 등).
2. 아니면 `ac.kr` 규칙을 쓴다. 정규식 `^([a-z0-9-]+\.)*[a-z0-9-]+\.ac\.kr$`에 맞으면 학교 키는 `<마지막 라벨>.ac.kr`이다(`cs.snu.ac.kr` → `snu.ac.kr`). `ac.kr`만 있는 도메인은 맞지 않는다.
3. 둘 다 아니면 400 `errors[email]` "대학 메일로만 가입할 수 있습니다."

추가로 정할 것:
- **판정 시점**: 가입 신청(signup)에서도 같은 판정으로 거부하고, 확인(verify)에서 다시 판정해 저장한다. 그 사이 운영자가 목록을 바꿨으면 확인 시점 기준이다.
- **설정**: `camgong.auth.extra-school-domains`(환경변수 `EXTRA_SCHOOL_DOMAINS`). 형식은 묶음을 `;`로, 묶음 안 도메인을 `,`로 나눈다. 예: `skku.edu,g.skku.edu;sogang.ac.kr,sg.ac.kr`. 빈 값이면 `ac.kr` 규칙만 쓴다.
  - 옛 `allowed-email-domains`(정확 일치)는 없앤다.
  - 기동할 때 형식을 검사한다. 빈 도메인, 같은 도메인이 두 묶음에 있는 경우는 기동 실패다.
- **도메인 판정은 서버가 진실**이다. 프론트는 이메일 형식만 검사한다.

### 2. 저장
- 마이그레이션 `V2__school.sql`:
  - `member.school VARCHAR(253) NOT NULL`.
  - `group_buy.school VARCHAR(253) NOT NULL`. 개설 때 개설자의 학교를 복사한다(바뀌지 않음).
  - 운영 데이터가 없으므로 기본값 없이 NOT NULL로 둔다. 로컬 DB는 다시 만든다(테스트 시드도 학교를 넣는다).
- 학교가 바뀌지 않으므로 복사본이 어긋날 일이 없다.

### 3. 목록 쿼리와 인덱스
- 로그인 목록: `WHERE school = :mySchool AND …` + 기존 정렬·커서.
- 비로그인 목록: `school` 파라미터가 있으면 같은 조건, 없으면 기존 그대로다.
- 인덱스: 003 목록이 쓰는 인덱스 앞에 `school`을 붙인 인덱스를 더한다. 비로그인 전국 목록은 기존 인덱스를 쓴다. 어떤 인덱스를 더할지는 백엔드가 `EXPLAIN`으로 정하고 측정에 남긴다.
- 학교 검색은 "검색어 → 학교 키 후보"를 먼저 찾고(결정 4), 목록은 **정확한 학교 키**로만 거른다(`LIKE '%x%'` 목록 쿼리 없음).

### 4. 학교 검색 (비로그인)
- `GET /api/schools?q=snu`: 공구가 하나라도 있는 학교 키 가운데 검색어가 들어간 것을 최대 10개 준다.
- 화면은 이 결과를 고르게 하고, 고른 키를 목록의 `school`로 보낸다.
- 공구가 없는 학교는 나오지 않는다(골라도 빈 목록이므로).

### 5. 접근 경계
- 로그인 회원의 상세, 새 참여, 수량 변경, 참여 취소에서 공구의 학교가 다르면 **404 Not Found**를 준다. 없는 공구와 같은 본문이다.
- 공구 머리를 읽는 공통 경로(003 상세, 004 `findHead`)에 학교 조건을 넣어 한 곳에서 막는다.
- 개설자 전용 경로(수정, 취소, 체크표)는 개설자 본인만 통과하므로 자연히 같은 학교다. 따로 고치지 않는다.
- 비로그인 상세는 지금처럼 401(로그인 요구)이다.

### 6. 응답 필드
- 목록 카드와 상세에 `school`(학교 키 문자열)을 더한다.
- 002 `member` 응답(로그인, verify, me)에도 `school`을 더해 화면이 "우리 학교" 표시를 하게 한다.

## 프론트 (008)

- 가입 화면 문구를 "대학 메일(ac.kr 등)"로 바꾼다.
- 목록 카드에 학교 표시를 단다.
- 비로그인 목록에는 학교 검색 입력을 둔다. `/api/schools` 자동완성으로 고르고, 고르면 목록 쿼리에 `school`을 붙인다. URL 쿼리에도 남겨 공유·새로고침에 유지한다.
- 로그인하면 학교 검색을 숨기고 "우리 학교 · snu.ac.kr" 머리말을 보인다.
- 목(MSW)과 실서버 e2e도 계약대로 맞춘다.

## 검증 (quickstart)

1. `snu.ac.kr`, `cs.snu.ac.kr`는 가입되고 같은 학교다.
2. `EXTRA_SCHOOL_DOMAINS=skku.edu,g.skku.edu`일 때 두 도메인 가입자는 같은 학교다.
3. `stanford.edu`, `gmail.com`, `ac.kr`, `fakeac.kr`은 400이다.
4. A대 회원 목록에 B대 공구가 0건이다. B대 공구 id로 상세·참여하면 404다.
5. 비로그인 목록에는 전국 공구가 나온다. `/api/schools?q=snu`로 고른 학교의 공구만 나온다.
6. 003 k6 목록 측정을 다시 돌려 같은 데이터에서 p95가 목표 안인지 기록한다(`docs/benchmarks/`).
