# API Contract: 학교 범위 (002·003·004 변경)

## 002 가입 (`POST /api/auth/signup`, `POST /api/auth/verify`)

- `email`의 도메인 규칙을 바꾼다(plan 결정 1). 허용되지 않으면 지금처럼 `400`이고 `errors: [{ "field": "email", "message": "대학 메일로만 가입할 수 있습니다." }]`.
- verify에서 판정이 실패하면(그 사이 추가 목록에서 빠짐) 같은 400이고 `errors`의 `field`는 `token`이다. 메시지는 "이 메일로는 더 이상 가입할 수 없습니다."
- 설정 키: `camgong.auth.allowed-email-domains`를 없애고 `camgong.auth.extra-school-domains`(`키=도메인,도메인;키=도메인`)를 쓴다.

## 002 회원 응답 (`login`, `verify`, `GET /api/auth/me`)

```json
{ "member": { "id": 12, "displayName": "홍길동", "school": "snu.ac.kr" } }
```

## 003 목록 `GET /api/groupbuys`

- **인증**: 선택. 세션이 있으면 쓴다(지금은 "헤더가 있어도 쓰지 않는다"였다).
- 새 쿼리 파라미터:

| 이름 | 값 | 설명 |
|------|-----|------|
| `school` | 학교 키(예: `snu.ac.kr`), 253자 이하 | 비로그인일 때만 쓴다. 이 학교 공구만 보여준다. 로그인했으면 무시하고 회원의 학교로 거른다 |

- 카드에 `"school": "snu.ac.kr"`를 더한다.
- 커서는 학교와 묶지 않는다(지금의 상태·카테고리 필터처럼). `sort`가 맞지 않거나 형식이 잘못된 커서만 400이다.
- 400 조건에 "`school`이 253자 초과"를 더한다. 길이 검사는 로그인 여부와 상관없이 먼저 한다(로그인이면 값은 쓰지 않지만 형식 오류는 400).
- 세션 쿠키가 만료·무효면 비로그인으로 다뤄 전국 목록을 준다(공개 경로라 401을 주지 않는다). 화면이 "우리 학교" 머리말을 띄운 상태에서 이렇게 되는 것은 알려진 한계다. 다음 보호 경로 요청의 401로 로그인 화면으로 간다.

## 003 내 활동 `GET /api/me/groupbuys`

- 바뀌지 않는다. 항목에 `school`을 더하지 않는다(내 활동은 늘 내 학교 공구뿐이다).

## 003 상세 `GET /api/groupbuys/{id}`

- 응답에 `"school"`을 더한다.
- 공구의 학교가 요청한 회원의 학교와 다르면 `404 Not Found`. 본문은 없는 공구와 같다.

## 004 참여·수량 변경·참여 취소

- 공구의 학교가 요청한 회원과 다르면 `404 Not Found`. 본문은 없는 공구와 같다.
- 다른 규칙은 그대로다.

## 새 엔드포인트 `GET /api/schools?q=`

**인증**: 불필요.

- `q`: 앞뒤 공백 무시, 1~50자, 소문자로 비교, `%`·`_`는 글자 그대로. 취소되지 않은 공구가 하나라도 있는 학교 키 가운데 `q`가 들어간 것을 사전순으로 최대 10개 준다.
- 성공 `200 OK`: `{ "items": ["snu.ac.kr", "snue.ac.kr"] }`. 없으면 `items: []`.
- `400`: `q`가 없거나 비었음, 또는 50자 초과(`errors`에 `q`).

## 바뀌지 않는 것

001 개설·수정·취소(공구의 학교는 개설자 학교로 자동), 005 마감 확정, 006 체크표, 007 알림.
