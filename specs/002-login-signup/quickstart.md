# Quickstart: 가입·로그인 검증

> 초안: 추천안 기준(사용자 결정 대기). 요청·응답은 [contracts/auth-api.md](contracts/auth-api.md), 규칙은 [data-model.md](data-model.md).

구현 후 가입·로그인이 end-to-end로 동작하는지 확인하는 시나리오다. 테스트에서는 메일 발송 대신 `LoggingMailSender`가 인증 링크의 토큰을 기록하고, 시간은 `MutableClock`으로 움직인다.

## 준비

- 001 quickstart의 준비(JDK 21, Docker, `useAffectedRows=true`).
- 허용 도메인: `school.ac.kr`(테스트용). 운영 값은 사용자 제공.
- 자동 테스트: `./gradlew test`.

## 시나리오

| # | 확인 내용 | 조작 | 기대 결과 | spec |
|---|-----------|------|-----------|------|
| 1 | 가입 신청 | 올바른 정보로 `POST /signup` | 202, 인증 메일 1통 기록, 로그인 불가 | US1-1, FR-001 |
| 2 | 인증 완료 | 기록된 토큰으로 `POST /verify` | 200 + 쿠키, `GET /me` 200, 로그인이 필요한 기능 사용 가능 | US1-2 |
| 3 | 개설자 이름 노출 | 가입한 회원이 공구 개설 후 다른 회원이 상세 | 개설자 이름이 가입 때 표시 이름 | US1-3, FR-013 |
| 4 | 이미 가입된 이메일 | 인증을 마친 이메일로 다시 신청 | 409 `ALREADY_REGISTERED` | US1-4 |
| 5 | 입력 검증 | 짧은 비밀번호, 형식 틀린 이메일, 공백 이름, 비동의 | 400, 필드별 사유 | US1-5, FR-017 |
| 6 | 이름 중복 | 이미 쓰이는 이름(대소문자·공백 무시)으로 가입 후 인증 | 인증 시 409 `DISPLAY_NAME_TAKEN`, 새 이름으로 다시 확인하면 가입 완료 | US1-7, US3-6, FR-003 |
| 7 | 비로그인 접근 | 헤더·쿠키 없이 상세·개설·참여·내 활동·알림 | 모두 401, 목록은 200 | US2-1·5, FR-008 |
| 8 | 로그인 | 올바른 정보 | 200 + 쿠키, 메인으로 가는 건 프론트 | US2-2, FR-009 |

| 11 | 인증 전 로그인 | 신청만 하고 로그인 | 401 (안내 문구는 결정 대기) | US2-6 |

| 13 | 재발송 | 1분 안 / 1분 뒤 / 24시간에 6번째 | 429 / 202 / 429(`retryAt`) | US3-2, FR-005, SC-011 |
| 14 | 만료·재사용 링크 | 25시간 뒤 토큰 / 이미 쓴 토큰 / 재발송 전 이전 토큰 | 410 / 409 `TOKEN_USED` / 무효 | US3-3·4, FR-004 |
| 15 | 인증 전 재제출 | 같은 이메일로 다른 정보 제출 | 새 정보로 바뀌고 새 메일 | US3-5, FR-006 |

## 헌법과의 대응

이 기능에는 헌법 IV 필수 대상이 없다. 시나리오 13·16·20(동시에도 정확한 한도·잠금·중복 방지)은 통합 테스트로 덮는다.
