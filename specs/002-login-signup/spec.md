## Clarifications

### Session 2026-10-26

- Q: 로그인 수단은? → A: 이메일 + 비밀번호. 소셜 로그인은 지금 넣지 않고, 나중에 추가할 수 있다.
- Q: 기숙사생 확인 방식은? → A: 학교 이메일 인증. 학교 이메일 주소로 가입하고, 메일로 온 링크를 확인해야 가입이 완료된다.
- Q: 표시 이름 규칙은? → A: 자유 닉네임이고 중복 불가. 이름 하나가 한 명으로 특정된다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 학교 이메일로 가입하고 인증해서 쓰기 (Priority: P1)

공구를 하고 싶은 기숙사생이 서비스에 처음 들어와 학교 이메일, 표시 이름, 비밀번호로 가입을 신청한다. 서비스가 그 이메일로 인증 메일을 보내고, 메일의 링크를 확인하면 가입이 완료되어 바로 로그인된 상태로 공구를 열거나 참여할 수 있다.
지금은 에브리타임 댓글로 이름을 남기는데, 이 기능이 "누가 참여했는지"를 서비스가 아는 회원으로 바꿔준다.

**Why this priority**: 회원이 없으면 개설도 참여도 불가능하다. 지금까지 만든 모든 기능이 이 기능 위에서 동작한다.

**Independent Test**: 가입하지 않은 사람이 가입을 신청하고 인증 메일의 링크를 확인해 가입을 마친 뒤, 로그인이 필요한 기능(예: 공구 개설 화면)에 들어갈 수 있는지, 공구 상세의 개설자 이름에 자기 표시 이름이 보이는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 가입하지 않은 사용자가 학교 이메일로 올바른 정보를 제출하면, **When** 가입을 신청하면, **Then** 그 이메일로 인증 메일이 발송되고 아직 로그인할 수 없다.
2. **Given** 인증 메일을 받은 사용자가 있고, **When** 유효 시간 안에 메일의 링크를 확인하면, **Then** 가입이 완료되어 로그인된 상태가 되고 바로 로그인이 필요한 기능을 쓸 수 있다.
3. **Given** 가입을 마친 회원이 공구를 열었고, **When** 다른 회원이 그 공구의 상세를 보면, **Then** 개설자 이름으로 가입 때 정한 표시 이름이 보인다.
4. **Given** 이미 인증을 마친 이메일이 있고, **When** 같은 이메일로 다시 가입하려 하면, **Then** 거부되고 이미 가입되었다고 안내된다.
5. **Given** 가입 화면에서, **When** 필수 항목을 비우거나 규칙에 맞지 않는 값(너무 짧은 비밀번호, 형식이 틀린 이메일, 공백뿐인 이름 등)을 넣으면, **Then** 신청이 거부되고 어떤 항목이 왜 잘못됐는지 안내된다.
6. **Given** 이미 다른 회원이 쓰는 표시 이름이 있고, **When** 같은 이름(대소문자·앞뒤 공백 무시)으로 가입하려 하면, **Then** 거부되고 이미 쓰는 이름이라고 안내된다.

### User Story 2 - 로그인하고 하던 일로 돌아가기, 로그아웃하기 (Priority: P1)

가입한 회원이 로그인하면 이후 요청에서 본인으로 식별된다. 로그인하지 않은 사용자가 공구 상세, 개설, 참여, 내 활동에 접근하려 하면 로그인을 요구받고, 로그인을 마치면 메인(공구 목록) 화면으로 돌아간다.
로그아웃하면 다시 비로그인이 된다.

**Why this priority**: 에브리타임 글의 링크로 들어온 사람이 로그인하고 서비스를 쓰는 길이고, 다른 기능이 "로그인한 회원만"을 전제한다.

**Independent Test**: 가입한 회원이 로그아웃 상태에서 로그인이 필요한 기능에 접근해 로그인을 요구받고, 로그인하면 메인으로 돌아가며, 로그아웃 뒤에는 같은 기능이 다시 막히는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 로그인하지 않은 사용자가 있고, **When** 공구 상세나 개설, 참여, 내 활동에 접근하면, **Then** 로그인을 요구받는다.
2. **Given** 로그인을 요구받은 사용자가 있고, **When** 올바른 정보로 로그인하면, **Then** 메인(공구 목록) 화면으로 돌아가고 이후 로그인이 필요한 기능을 쓸 수 있다.
3. **Given** 로그인한 회원이 있고, **When** 로그아웃하면, **Then** 이후 로그인이 필요한 기능이 다시 막히고, 로그아웃 전에 쓰던 인증 정보로는 접근할 수 없다.
4. **Given** 로그인 화면에서, **When** 틀린 정보로 로그인하면, **Then** 거부되고 정보가 틀렸다고만 안내된다(어느 쪽이 틀렸는지, 계정이 있는지는 알려주지 않는다).
5. **Given** 로그인하지 않은 사용자가 있고, **When** 공구 목록을 열면, **Then** 로그인 없이 볼 수 있다.
6. **Given** 가입을 신청했지만 인증을 마치지 않은 사용자가 있고, **When** 로그인하려 하면, **Then** 거부되고 이메일 인증이 필요하다고 안내된다.

### User Story 3 - 학교 이메일이 아닌 사람 걸러내기, 인증 메일 문제 풀기 (Priority: P2)

학교 이메일이 아닌 주소로는 가입할 수 없고, 인증 메일을 못 받았거나 링크가 만료됐을 때 다시 받을 수 있다.

**Why this priority**: 이 서비스의 신뢰가 "같은 학교 사람끼리"에 있고, 인증이 막히면 가입 자체가 막히므로 복구 길이 필요하다. 다만 기본 가입·로그인(US1, US2)이 먼저다.

**Independent Test**: 학교 이메일이 아닌 주소로 가입을 시도해 거부되는지, 인증 메일을 다시 받고 만료된 링크를 확인해 보는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 학교 이메일이 아닌 주소가 있고, **When** 가입을 신청하면, **Then** 거부되고 학교 이메일만 쓸 수 있다고 안내된다.
2. **Given** 인증 메일을 받지 못한 사용자가 있고, **When** 인증 메일 재발송을 요청하면, **Then** 새 인증 메일이 발송된다. 직전 발송 후 1분이 지나지 않았으면 잠시 뒤 다시 시도하라고 안내된다.
3. **Given** 발송된 지 24시간이 지난 링크가 있고, **When** 링크를 확인하면, **Then** 인증되지 않고 만료되었다고 안내되며 재발송을 요청할 수 있다.
4. **Given** 이미 인증에 쓴 링크가 있고, **When** 다시 확인하면, **Then** 이미 인증되었다고 안내된다.
5. **Given** 인증을 마치지 않은 이메일이 있고, **When** 같은 이메일로 가입 정보를 다시 제출하면, **Then** 새 정보로 바뀌고 새 인증 메일이 발송된다.

---

### User Story 4 - 로그인 남용 막기 (Priority: P3)

같은 계정으로 틀린 로그인을 반복해서 비밀번호를 알아내려는 시도를 일정 횟수 뒤에 막는다.

**Why this priority**: 공개 서비스이므로 최소한의 방어가 필요하지만, 정상 흐름보다 뒤다.

**Independent Test**: 같은 계정으로 틀린 로그인을 반복해 정해진 횟수 뒤 잠기는지, 올바른 정보로도 잠긴 동안은 거부되는지, 시간이 지나면 풀리는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 같은 계정으로 연속 5번 틀린 로그인이 있었고, **When** 6번째 로그인을 시도하면, **Then** 올바른 정보여도 15분 동안 거부되고 잠시 뒤 다시 시도하라고 안내된다.
2. **Given** 잠금 시간이 지났고, **When** 올바른 정보로 로그인하면, **Then** 로그인된다.
3. **Given** 4번 틀린 뒤 올바른 정보로 로그인했고, **When** 이후 다시 틀리면, **Then** 실패 횟수는 처음부터 다시 센다.

---

### Edge Cases

- 가입 신청을 더블 클릭 등으로 짧은 시간에 여러 번 제출하면? → 회원 정보는 하나만 만들어지고 인증 메일이 연속으로 쏟아지지 않는다(FR-015).
- 이메일의 대소문자나 앞뒤 공백이 달라도 같은 이메일인가? → 같은 이메일로 본다(FR-002).
- 로그인 유지 기간이 지난 뒤 로그인이 필요한 기능을 쓰면? → 로그인을 요구하고, 로그인하면 메인으로 돌아간다.
- 여러 기기에서 동시에 로그인하면? → 모두 허용되고, 한 기기에서 로그아웃해도 다른 기기는 유지된다.
- 이미 로그인한 사람이 로그인·가입 화면에 들어오면? → 메인으로 보낸다.
- 인증 링크를 가입을 신청한 기기와 다른 기기에서 열면? → 인증은 성공하고, 로그인은 링크를 연 기기에서 이뤄진다.
- 로그아웃한 뒤 뒤로 가기로 이전 화면을 보면? → 로그인이 필요한 데이터는 다시 요청하지 않으면 보이지 않고, 요청하면 로그인을 요구한다.
- 인증 메일 발송이 실패하면? → 사용자에게 알리고 재발송을 요청할 수 있게 한다.
- 비밀번호나 인증 정보가 로그, 오류 메시지, 다른 회원에게 보이면? → 어떤 경우에도 보이지 않는다.
- 인증 링크를 추측하거나 다른 사람 것을 쓰면? → 링크는 추측할 수 없어야 하고, 한 번 쓰면 다시 쓸 수 없다(FR-004).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 가입하지 않은 사용자는 이메일과 비밀번호로 가입을 신청할 수 있어야 한다. 신청하면 이메일로 인증 메일이 발송되고, 인증을 마치기 전에는 로그인할 수 없다. 인증을 마치면 가입이 완료되어 바로 로그인된 상태가 되어야 한다. 소셜 로그인 등 다른 수단은 이 기능에서 지원하지 않는다.
- **FR-002**: 가입 신청 시 이메일, 표시 이름, 비밀번호를 필수로 입력받아야 한다. 비밀번호는 8자 이상 72바이트 이하여야 하고, 이메일은 형식이 올바라야 하며 앞뒤 공백과 대소문자를 무시하고 같은 것은 같은 이메일로 본다. 이미 인증을 마친 이메일이면 거부하고 알려야 한다. 비밀번호는 원문 그대로 저장되거나 어디에도 노출되어서는 안 된다.
- **FR-003**: 표시 이름은 2자 이상 20자 이하이고 공백만으로 이루어질 수 없어야 한다. 다른 회원이 이미 쓰는 이름(대소문자·앞뒤 공백 무시)과 같으면 거부하고 알려야 한다. 인증을 마친 회원의 이름만 점유로 본다.
- **FR-004**: 가입은 학교 이메일 주소로만 가능해야 하고, 허용되지 않은 도메인의 주소는 거부하고 이유를 알려야 한다. 인증 메일의 링크는 열면 확인 화면이 나오고 사용자가 확인하는 동작으로 인증이 이뤄져야 하며(메일 보안 검사가 링크를 미리 열어도 소진되지 않도록), 링크는 추측할 수 없어야 하고, 발송 후 24시간 동안 한 번만 유효해야 한다. 만료되었거나 이미 쓴 링크는 인증되지 않고 그 이유를 알려야 한다.
- **FR-005**: 인증 메일 재발송을 요청할 수 있어야 한다. 직전 발송으로부터 1분이 지나지 않았으면 거부하고 잠시 뒤 다시 시도하라고 안내해야 한다. 새로 발송하면 이전 링크는 무효가 된다.
- **FR-006**: 인증을 마치지 않은 이메일로 가입 정보를 다시 제출하면 새 정보로 바뀌고 새 인증 메일이 발송되어야 한다. 인증을 마치지 않은 가입 정보는 표시 이름이나 이메일을 점유하지 않는다.
- **FR-007**: 로그인하면 이후 요청에서 본인으로 식별되어야 한다. 로그인 상태는 마지막으로 쓴 때로부터 14일 동안 유지되고, 쓸 때마다 연장되어야 한다.
- **FR-008**: 로그인이 필요한 기능(공구 상세, 개설, 수정, 취소, 참여, 수량 변경, 참여 취소, 내 활동)은 로그인하지 않은 사용자에게 거부되어야 하고, 로그인을 요구해야 한다. 공구 목록은 로그인 없이 볼 수 있다.
- **FR-009**: 로그인 요구를 받은 사용자가 로그인을 마치면 메인(공구 목록) 화면으로 돌아가야 한다.
- **FR-010**: 로그인 실패 시에는 정보가 틀렸다고만 안내하고, 계정이 존재하는지나 어느 쪽이 틀렸는지는 알려서는 안 된다. 인증을 마치지 않은 계정은 이메일 인증이 필요하다고 안내할 수 있다.
- **FR-011**: 같은 이메일로 연속 5번 로그인에 실패하면(가입되지 않은 이메일도 똑같이 세어, 잠금 안내가 계정 존재 여부를 드러내지 않아야 한다) 올바른 정보여도 15분 동안 로그인을 거부하고 잠시 뒤 다시 시도하라고 안내해야 한다. 성공하면 실패 횟수를 처음부터 센다.
- **FR-012**: 로그아웃하면 그 로그인 상태는 즉시 무효가 되어, 이전 인증 정보로는 어떤 기능에도 접근할 수 없어야 한다. 다른 기기의 로그인 상태에는 영향이 없다. 한 회원은 여러 기기에서 동시에 로그인할 수 있다.
- **FR-013**: 다른 회원에게 보이는 회원 정보는 표시 이름뿐이어야 한다. 이메일과 비밀번호는 어떤 화면과 응답에도 다른 회원에게 보이지 않는다.
- **FR-014**: 이 기능이 적용되면 임시 식별 방식(요청 머리글에 회원 번호를 직접 담는 방식)은 더 이상 요청자를 인증해서는 안 된다. 그 방식으로는 어떤 요청도 인증되지 않아야 한다.
- **FR-015**: 같은 가입 신청이나 인증 메일 재발송 요청이 짧은 시간에 여러 번 와도 회원 정보는 하나만 만들어지고 인증 메일이 연달아 발송되어서는 안 된다(FR-005의 간격 규칙을 따른다).
- **FR-016**: 가입과 인증, 로그인 요청이 거부될 때는 어떤 규칙을 어겼는지 사용자가 알 수 있는 이유를 돌려줘야 한다(FR-010의 로그인 실패 안내는 예외).
- **FR-017**: 가입 신청은 개인정보 수집·이용에 동의해야 접수된다. 서비스는 동의한 시각과 동의한 안내문 버전을 회원 정보에 남긴다. 동의하지 않으면 신청이 거부되고 동의가 필요하다고 안내된다.

### Key Entities

- **회원(Member)**: 서비스를 쓰는 기숙사생. 표시 이름(중복 불가), 이메일, 인증 정보(비밀번호), 이메일 인증 여부, 가입 시각을 가진다. 인증을 마친 회원만 로그인할 수 있다. 공구를 열고 참여하는 모든 기능의 행위자다.
- **이메일 인증 요청**: 인증을 마치지 않은 가입 신청에 딸린 한 번만 쓰는 링크. 발송 시각과 만료 시각, 사용 여부를 가진다. 회원 하나에 유효한 것은 하나뿐이다.
- **로그인 상태(Session)**: 로그인한 한 기기의 인증 상태. 한 회원이 여럿 가질 수 있고, 로그아웃이나 유지 기간 만료로 사라진다.
- **로그인 실패 기록**: 계정별 연속 실패 횟수와 잠금 시각. 남용 방어에만 쓴다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 신규 사용자가 인증 메일을 받은 뒤 링크를 확인해 로그인된 상태로 공구 목록을 보기까지 1분 이내가 걸린다.
- **SC-002**: 가입 신청을 제출하면 95%가 1분 이내에 인증 메일이 발송된다.
- **SC-003**: 로그인이 필요한 모든 기능이 비로그인 요청의 100%를 거부하고, 로그인을 마친 사용자의 100%가 메인으로 돌아간다.
- **SC-004**: 임시 머리글 방식으로 회원인 척하는 요청이 0건 인증된다(위조 시도 100% 거부).
- **SC-005**: 다른 회원에게 노출되는 회원 정보는 표시 이름뿐이며, 이메일과 비밀번호의 노출은 0건이다.
- **SC-006**: 같은 계정의 연속 5회 실패 뒤 15분 동안의 로그인 시도가 100% 거부되고, 잠금이 풀린 뒤에는 정상 로그인이 된다.
- **SC-007**: 로그아웃 뒤 이전 로그인 상태로의 접근 성공이 0건이다.
- **SC-008**: 허용되지 않은 도메인의 이메일로 가입이 완료되는 경우가 0건이고, 만료·사용된 인증 링크로 인증이 되는 경우가 0건이다.
- **SC-009**: 비밀번호 원문이 저장소, 로그, 응답, 오류 메시지에 남는 경우가 0건이다.
- **SC-010**: 로그인 요청의 95%가 1초 이내에 결과를 받는다.

## Assumptions

- 회원 탈퇴, 비밀번호 재설정, 프로필(표시 이름) 수정은 MVP 범위 밖이다. 비밀번호를 잊은 경우에는 운영자가 직접 처리한다.
- 소셜 로그인은 이번에 넣지 않는다. 나중에 추가할 수 있도록 이메일 로그인 외 수단이 들어올 자리는 막지 않는다.
- 학교 이메일 인증은 "같은 학교 구성원"임을 확인하는 것이고, 기숙사에 실제로 사는지는 확인하지 않는다. 기숙사 거주 확인은 이번 범위 밖의 알려진 한계다.
- 허용하는 학교 이메일 도메인은 운영 설정이며, 구체적인 값은 구현·운영 시 정한다.
- 인증 메일을 보내는 수단과 발송 신뢰성은 plan에서 정한다. 이 spec은 메일이 발송된다는 동작까지만 정한다.
- 가입은 인증을 마친 순간 완료되고 자동으로 로그인된 상태가 된다.
- 로그인 유지 14일, 실패 5회 후 15분 잠금, 비밀번호 8자 이상, 인증 링크 24시간, 재발송 간격 1분은 일반적인 기본값이며 필요하면 조정한다.
- 대량 가입 신청 남용 방어(속도 제한 등)는 MVP에서 다루지 않는다.
- 로그인 후 돌아가는 곳은 메인(공구 목록)이다(도메인 결정 G03). 에타 링크로 들어온 사용자가 원래 공구 상세로 돌아가는 동작은 이 결정으로 제외된다.
- 비밀번호, 메일 발송 계정 정보 등 인증 관련 비밀 값은 코드와 저장소에 넣지 않는다. 저장소가 공개이므로 환경 설정으로만 주입한다.
- 이 기능이 끝나면 임시 식별 방식이 사라지고, "로그인 전에는 공개 배포·실제 운영을 하지 않는다"는 제한(architecture 6.5)이 풀린다.
