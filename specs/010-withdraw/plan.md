# Implementation Plan: 회원 탈퇴(익명화)

**Branch**: `010-withdraw` | **Date**: 2026-11-19 | **Spec**: [spec.md](spec.md)

## Summary

로그인한 회원이 비밀번호를 다시 넣고 탈퇴한다. 회원 행은 남기고 이름·이메일·비밀번호를 익명값으로 바꾼다. 공구·참여 기록은 그대로 둔다. 모집 중(`OPEN`, 마감 확정 대기 포함) 공구에 있으면 거부한다. 계약은 [contracts/withdraw-api.md](contracts/withdraw-api.md).

## Technical Context

기존과 같다: Java 21, Spring Boot 4.1.2, MySQL 8.4(Flyway), React/Vite/TS. 테스트는 Testcontainers MySQL 통합 테스트, 프론트는 Vitest+MSW와 Playwright.

## Constitution Check

- 동시성: 탈퇴와 참여·개설 경쟁을 결정 3으로 막고 통합 테스트로 증명한다.
- 테스트 먼저: 각 태스크는 실패하는 테스트부터 쓴다.
- 문서 소유: `docs/`·`specs/`는 관제탑. 작업 세션은 코드만 고친다.

## 결정 (research)

### 1. 익명화 방식 — 행은 남기고 값만 바꾼다
- 이유: `group_buy.organizer_id`, `participation.member_id`가 FK로 회원을 가리킨다. 행을 지우면 다른 사람의 공구 기록이 깨진다.
- 바꾸는 값:
  - `name` = `탈퇴한 회원`(화면 표시 그대로. 조회 쿼리를 고칠 필요가 없다).
  - `display_name_key`, `email`, `email_key` = `NULL`. UNIQUE는 NULL 여러 개를 허용하므로 이름·이메일이 풀린다.
  - `password_hash` = 어떤 비밀번호와도 맞지 않는 값.
  - `withdrawn_at` = 탈퇴 시각.
- 대안 "`withdrawn-{id}` 같은 자리표시 키"는 버렸다. 그 이름으로 먼저 가입한 사람이 있으면 UNIQUE 충돌이 난다.
- 마이그레이션 `V3__withdraw.sql`(009가 V2): 세 컬럼을 NULL 허용으로 바꾸고 `withdrawn_at DATETIME(6) NULL`을 더한다.
- 로그인은 `email_key`로 찾으므로 탈퇴 계정은 "없는 계정"과 같은 경로(더미 해시 비교, 401)를 탄다(FR-007).

### 2. 막는 조건
- 회원의 참여 행 가운데 공구 `status = 'OPEN'`인 것이 하나라도 있으면 거부한다.
- 개설자도 참여 행을 가지므로(001: 개설 때 개설자 참여 행 생성) 한 쿼리로 개설자와 참여자를 모두 잡는다.
- 마감 시각이 지난 `OPEN`(표시 상태 `PENDING_CLOSE`)도 여기에 들어간다.
- 응답에는 막는 공구 목록(`blockers`)을 담는다. 역할(`ORGANIZER`/`PARTICIPANT`)과 표시 상태를 함께 넣어 화면이 무엇을 할지 안내하게 한다.

### 3. 처리 순서와 동시성 — 회원 행 잠금
- **트랜잭션 밖(LoginService와 같은 방식)**: 회원을 읽어 `email_key`를 얻는다(이미 NULL이면 401). 잠금 상태면 429. 비밀번호가 틀리면 `countAttempt`(트랜잭션 밖 한 문장이라 바로 커밋)를 실행하고 400을 준다. 트랜잭션 안에서 세면 예외 롤백으로 횟수가 사라진다.
- **트랜잭션 안**: ① `member … FOR UPDATE` ② `withdrawn_at IS NULL`이 아니면 401(동시에 두 번 온 탈퇴) ③ 막는 조건 확인(일반 SELECT, 잠금 읽기 금지. `FOR SHARE`면 006 체크표 읽기와 교착할 수 있다) ④ 익명화와 삭제(결정 5).
- 탈퇴 트랜잭션은 첫 문장으로 `SELECT … FROM member WHERE id = ? FOR UPDATE`를 실행한다. 이 잠금 다음에 막는 조건을 읽으므로, 잠금을 기다리는 동안 커밋된 참여가 보인다(InnoDB 스냅샷은 첫 일반 SELECT에서 잡힌다).
- 참여(004 참여·수량 변경은 제외하고 **새 참여만**)와 개설(001)은 트랜잭션 첫 문장으로 `SELECT withdrawn_at FROM member WHERE id = ? FOR SHARE`를 실행한다. `withdrawn_at`이 있으면 401(로그인 풀림과 같은 응답)로 거부한다.
- 잠금 순서는 항상 member → group_buy다. 탈퇴는 group_buy를 잠그지 않으므로 교착이 없다.
- 004 경합 측정(마지막 수량 경쟁)에는 회원별로 서로 다른 행의 공유 잠금이 하나 더해질 뿐이다. 측정을 다시 돌려 차이를 기록한다(확인 대상).
- 수량 변경·참여 취소는 이미 있는 참여 행만 다루므로 잠그지 않는다. 탈퇴 뒤에는 세션이 없어 요청이 401로 끝난다.

### 4. 탈퇴한 회원의 세션을 막는 곳
- `AuthFilter`가 `withdrawn_at`이 있는 회원의 세션은 없는 것으로 다룬다. 로그인이 회원을 읽은 뒤 세션을 넣기 전에 탈퇴가 커밋되는 경쟁에서도, 이 한 곳에서 모든 경로가 막힌다.

### 4-1. 이름 예약과 늦은 알림
- 표시 이름 "탈퇴한 회원"(002 정규화 키 기준)은 가입 때 거부한다(400 `errors[displayName]`). 살아 있는 회원이 탈퇴한 회원인 척하지 못하게 한다.
- 007 알림 쓰기는 받는 사람 가운데 `withdrawn_at`이 있는 회원을 뺀다. 공구 완료·취소 직후 탈퇴하면 비동기로 늦게 쓰는 알림이 남을 수 있어서다.

### 4-2. 비밀번호 재확인과 잠금
- 002 로그인 실패 잠금(`login_attempt`, 5회·15분)을 같은 키(`email_key`)로 공유한다.
- 틀리면 실패 횟수를 올리고 400 `INVALID_PASSWORD`를 준다. 잠겨 있으면 429 `LOGIN_LOCKED`를 준다.
- 401을 쓰지 않는 이유: 프론트는 401을 받으면 로그인 화면으로 보낸다.

### 5. 함께 지우는 것
같은 트랜잭션에서 지운다. 단 `login_session`만 예외다(아래).
- 그 회원의 `login_session` 전부: **커밋 직후 따로 지운다**(2026-11-19 구현 중 변경). 트랜잭션 안(회원 행 X 잠금)에서 지우면 세션 행을 넣는 문장 모양에 따라 교착할 수 있다. 실제로 재현된 것은 테스트 도우미의 `INSERT … ON DUPLICATE KEY UPDATE`와의 교착이고, 실제 로그인(단순 INSERT)과의 경쟁 900회에서는 재현되지 않았다(백엔드 세션 정정, 2026-11-19). 그 사이 남거나 새로 들어온 세션은 `AuthFilter`가 탈퇴 회원이라 거부한다(결정 4). 커밋 후 삭제가 실패해도 응답은 204이고 정리 작업이 TTL로 지운다.
- `notification` 가운데 `recipient_id`가 그 회원인 것.
- 그 이메일 키의 `pending_signup`, `login_attempt`.

`create_guard`는 개인정보가 아니라 남긴다(정리 작업 대상).

남기는 값: `member.school`(메일 도메인에서 나온 학교 키, 예 `snu.ac.kr`). 사람을 특정하지 않고 NOT NULL·CHECK 제약도 있어 남긴다. 동의 시각·버전, 가입 시각도 남는다. 회원이 쓴 공구 글(제목·설명)은 다른 참여자의 기록이라 남긴다(동의문 "함께한 공구 기록은 남습니다").

## 프론트 (008)

- 내 활동 화면 아래에 "탈퇴" 영역을 두고, 대화상자에서 비밀번호를 입력받고 "되돌릴 수 없음"을 확인받는다.
- 409면 `blockers`를 목록으로 보여주고 각 공구로 링크한다. 안내 문구(위에서부터 먼저 맞는 것):
  - 상태가 `PENDING_CLOSE`: "확정된 뒤 다시 시도하세요". 개설자여도 이 문구다. 마감 지난 공구는 취소할 수 없다(001 `NOT_MODIFIABLE`).
  - 개설자: "공구를 취소하세요".
  - 참여자: "참여를 취소하세요".
- 성공하면 세션 상태를 비우고 목록으로 이동해 "탈퇴했어요" 안내를 보여준다.
- 목(MSW)도 계약대로 만든다.
- 동의문 본문(`docs/consent-v1.md`)을 가입 화면에 `<details>`로 넣는다. 이 기능과 함께 한다.

## 검증 (quickstart)

1. 진행 중 공구가 없는 회원으로 탈퇴한다.
   - 204, 쿠키가 삭제된다.
   - 다른 브라우저의 세션도 401이 된다.
   - 같은 이메일·비밀번호 로그인은 401이다.
2. 완료 공구의 체크표에서 "탈퇴한 회원" 줄의 수량·금액·체크가 유지되고, 개설자가 계속 체크할 수 있다.
3. 같은 이메일로 새로 가입할 수 있고, 옛 표시 이름도 쓸 수 있다.
4. 모집 중 공구의 개설자, 참여자, 마감 지난 OPEN 공구 참여자의 탈퇴는 각각 409와 `blockers`를 받는다.
5. 비밀번호를 5번 틀리면 429가 되고, 로그인도 잠긴다.
6. 탈퇴와 새 참여를 동시에 100회 반복해도 "탈퇴했는데 OPEN 공구에 참여 행이 있음"이 0건이다.
