# 체크표 응답 시간 (006, 기록용)

헌법 II의 비교 측정 대상은 아니고 SC-002(참여자 50명 공구의 체크표 요청 95%가 1초 이내)의 수치를 환경과 함께 남긴다.

## 환경과 방법

한 대의 Apple M5(10코어, 32GB)에서 앱(`java -Xms512m -Xmx512m -jar`, `benchmark` 프로파일 → 풀 20; jar는 Java 21 툴체인으로 컴파일, 실행은 PATH의 JDK 25), MySQL 8.4 컨테이너(OrbStack), k6(`grafana/k6` 컨테이너)를 모두 돌렸다. 시드: `load/seed.sql`(회원·세션) + `load/seed-check.sql`(모집 완료 공구 1건, 개설자 + 참여자 50명, 입금 확인 약 1/3·수령 확인 약 1/5). 시나리오: `load/k6/check-sheet.js` — 개설자 세션으로 체크표(`filter` 없음)를 5 VU가 30초 동안 반복 요청하고, 응답이 200이며 `rows`가 50개인 것만 성공으로 센다.

## 결과

| 항목 | 결과 | 목표 |
|------|------|------|
| 요청 수 / 실패 | 38,915건 / 0 (검사 100% 통과) | |
| 처리량 | 약 1,297 req/s | |
| 응답 시간 p95 / p99 / 최대 | 5.3ms / 7.1ms / 17.1ms | p95 1초 이내 (SC-002) |

## 한계

- 일회성 측정(반복 1회), 한 기계에서 앱·DB·k6 동거, 확인 상태가 섞인 50명 한 공구만 봤다. 쿼리 수가 참여자 수와 무관함은 `CheckSheetQueryCountIT`가 따로 지킨다.
- 체크 쓰기(입금·수령 PUT)의 응답 시간은 측정하지 않았다(목표가 없고, 한 행을 조건부 `UPDATE`하는 요청이다).
